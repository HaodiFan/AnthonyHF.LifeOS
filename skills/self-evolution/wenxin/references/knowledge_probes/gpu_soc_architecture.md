# GPU / SoC 架构 知识抽样

## 该领域的"鲜度衰减曲线"

**衰减快**（离开 1-2 年就需要重新跟进）：
- 具体架构代号的 spec（Volta / Ampere / Hopper / Blackwell 的具体参数）
- CUDA 版本特性、新指令集
- 具体工具链（Nsight、CUTLASS 等）的 API 变化
- 最新工艺节点的具体特性

**衰减慢**（10 年后仍然在）：
- SIMT / SIMD 的核心抽象
- Memory hierarchy 的设计哲学
- 互联拓扑的权衡逻辑
- 性能建模的核心方法（roofline 等）
- 跨代架构演进的"第一性原理"

**完全不衰减**：
- "为什么 GPU 是这种架构"的思维方式
- 在性能 / 功耗 / 面积间做权衡的判断
- 看一段 workload 能预判它在不同架构上会怎么跑的直觉

## L3 级问题（验证"做过"）

### 1. SM 内部基本结构

**题目**：一个 SM（Streaming Multiprocessor）里大致包含哪些主要的执行单元？warp 在 SM 上是怎么调度的？

**合格答案的特征**：
- 提到 CUDA cores / Tensor Cores / SFU / LSU 等执行单元
- 描述 warp scheduler 的基本机制（每个 warp 32 lanes，scheduler 在多个 warp 间切换隐藏延迟）
- 能区分 active warp / resident warp 的概念

**不合格的信号**：
- 答得很笼统（"SM 就是 GPU 里执行计算的单元"）
- 把 warp 和 thread 概念搞混
- 完全不提调度机制

### 2. Memory hierarchy

**题目**：GPU 里从最快到最慢的几级 memory 大致是怎么分层的？为什么要这么分？

**合格答案**：
- 从 register → shared memory / L1 → L2 → HBM/DRAM 的层次
- 能解释每级的**延迟和带宽数量级差异**
- 能讲为什么要 shared memory（程序员可控的 cache）

### 3. 性能建模工具

**题目**：你们做 simulation 用的是什么级别的工具？trace-based 还是 cycle-accurate？区别是什么？

**合格答案**：
- 能说清两种 sim 的差别（trace 快但精度低，cycle-accurate 慢但精度高）
- 能描述自己具体用过什么（GPGPU-Sim / 公司内部工具）
- 能说出"什么时候用哪种"

## L4 级问题（验证"懂为什么"）

### 4. Tensor Core 设计哲学

**题目**：从 Volta 引入 Tensor Core 之后，每代都在演进。你怎么理解 Tensor Core 这个设计的"为什么"——为什么不用更多 CUDA core 而是引入一种新的执行单元？

**合格答案**：
- 能从 throughput vs flexibility 的权衡角度回答
- 能讲到矩阵乘法是 AI workload 的瓶颈，专用单元 ROI 比堆 CUDA core 高
- 能讲不同代的 Tensor Core 演进逻辑（精度类型扩展、稀疏支持、Transformer Engine）

**不合格**：只会说"Tensor Core 是给 AI 用的，更快"。

### 5. NVLink vs PCIe 的权衡

**题目**：对于多 GPU 系统，NVLink 解决了什么 PCIe 解决不了的问题？这种设计的代价是什么？

**合格答案**：
- 带宽 / 延迟差异的具体数量级
- topology 的差异（NVLink 可以做 mesh / ring / NVSwitch）
- **代价**：成本、power、复杂度、生态锁定

### 6. AI workload 与 GPU 架构的双向影响

**题目**：你怎么看 Transformer 架构的流行对 GPU 架构演进的影响？反过来 GPU 架构又怎么影响了模型设计？

**合格答案**：能讲出**双向影响**：
- Transformer → 推动 Tensor Core / 大 HBM / NVLink 的进化
- GPU → MoE / FlashAttention 这些设计是为了"友好 GPU 架构"

只能讲单向 → L3+，不到 L4。

## L5 级问题（验证"知道自己不知道什么"）

### 7. 认知边界

**题目**：在 GPU / SoC 架构这个领域，你现在还**不知道什么**？或者你觉得自己理解还不够深的地方在哪？

**合格答案**（真 L5）的特征：
- 能列出 3 个以上具体子方向，每个都能说"我对 X 的理解还停留在 Y 层，没到 Z"
- 例如："我对 power delivery network 的理解还停留在框架级，没真正做过 IR drop 的具体优化"
- 例如："我对最新 Blackwell 架构的 NVL72 这种系统级集成只看了 keynote，没深入看技术细节"

**不合格**（伪 L4 的信号）：
- "都还行"、"还可以"、"主要是不够 deep"
- 无法说出具体子方向

### 8. 反例题

**题目**：你做过的某个架构决策 / simulation 结论，**回头看是错的**——能讲一个吗？

**合格答案**：能具体到某个 trade-off、当时怎么判断的、后来发现哪里错了、错的根本原因是什么。

**不合格**：说"我们做的都挺好的"或讲不出具体反例。

## 时间距离调整规则

| 时间距离 | 问哪几题 | 跳过哪几题 |
|---|---|---|
| **近期 1-2 年（仍在做）** | 1, 2, 3, 4, 5, 6, 7, 8 都可以 | 无 |
| **中期 3-5 年（离开但近期跟进过）** | 4, 5, 6, 7, 8（框架级 + 元认知） | 1, 2, 3 里"具体工具"细节 |
| **远期 5+ 年（离开很久）** | 7, 8 + 改造版的 4, 5（用粗粒度问） | 所有 L3 题 |

**改造版举例**：
- 远期问 4 不要问"Tensor Core 演进"——问 "你怎么理解 GPU 这种'专用计算单元'的设计哲学"
- 远期问 5 不要问"NVLink 具体带宽"——问 "为什么 GPU 互联是 GPU 系统设计的核心问题"

## 附：当用户回答这些题时，常见的"伪 L4 信号"

- **关键词堆砌但缺乏关联**：把 "warp / SM / Tensor Core / HBM / NVLink" 都说一遍但不能讲它们怎么协同
- **过度精准的数字**：报出"H100 有 528 个 Tensor Core"这种**只有官方文档才有的精确数字**——可能是死记硬背，问"为什么是 528 不是 512"会露馅
- **避谈权衡**：所有问题都用"X 更好"回答，从不说"X 在 A 场景好但 B 场景不好"
- **避谈失败**：问反例时无法说出具体错过的判断
