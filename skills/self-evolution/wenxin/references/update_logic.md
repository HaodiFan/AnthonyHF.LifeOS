# 持续迭代规则（update_logic.md）

「问心」阶段 6 的详细规则。

## 核心原则

### 「问心」不是一次性的

人是变化的。能力会成长 / 衰退；外号会需要演化；新的里程碑会发生。

「问心」必须**支持持续追踪**——不是每次都重头来，而是**累积式更新**。

### 三种更新模式（混合粒度）

| 模式 | 触发场景 | 工作量 | 输出 |
|---|---|---|---|
| **A · 完全重跑** | 重大变化（换工作 / 创业失败 / 转行）| 高（重走阶段 0-5）| 新报告 + 旧版归档 |
| **B · 局部更新** | 部分维度有变化 | 中（针对维度增量追问）| 部分字段更新 + 对比页 |
| **C · 里程碑追加** | 单一事件（融资 / 完成项目）| 低（自动推导影响）| 里程碑追加 + 维度微调 |

---

## 模式 A · 完全重跑

### 触发条件

- 用户主动选择 A
- 距上次更新 ≥ 12 个月（建议提示重跑）
- 用户表达"我变了很多 / 之前评估不准"

### 工作流

```
1. 自动归档当前 WENXIN_REPORT.md → archive/[YYYY-MM-DD].md
2. 删除当前 WENXIN_REPORT.md（或者重命名 .old 备份）
3. 走完整的阶段 0-5
4. 生成新 WENXIN_REPORT.md
5. 在持续迭代记录段加一条 "完全重跑" 记录
6. 生成 compare.html（如果有归档版本可对比）
```

### 持续迭代记录格式

```markdown
### 2027-08-12 · 模式 A 完全重跑
**触发**: 用户主动 / 距上次 12 个月 / 重大变化
**变化概要**:
- 外号: [旧] → [新]
- 主线: [旧] → [新]
- 雷达维度: 重新评估，新拼接组合 [旧组合] → [新组合]
**归档**: archive/[旧版日期].md
**对比页**: public/compare.html
```

## 模式 B · 局部更新

### 触发条件

- 用户主动选择 B
- 用户报告"我在 X 维度上有提升 / 衰退"
- 距上次更新 3-6 个月（推荐）

### 工作流

```
1. 呈现当前 WENXIN_REPORT.md 的雷达图
2. 让用户勾选哪些维度有变化（多选）
3. 对每个勾选的维度做精准追问：
   - 现在的水位估计是？
   - 新的证据 / 事件是什么？
   - 是否有新的 unique outcomes？
4. 自动判断：
   - 有没有维度变化 ≥ 30% → 触发外号重审视（见下文）
   - 主线是否还成立 → 触发主线复核
5. 更新 WENXIN_REPORT.md 中相关字段
6. 自动归档旧版
7. 生成 compare.html
```

### 局部追问的"单维度模板"

针对一个维度做追问时的标准流程：

```
问心：你说"商业转化"有变化。当前评估是 45%。
      让我问几个具体的——

      1. 最近 6 个月，你在"商业转化"上做的最有代表性的一件事是什么？
      2. 这件事的结果是？（具体数字 / 反馈）
      3. 之前 45% 的 gap（产品化、销售）你补了哪部分？
      4. 你现在主观估计这个维度的水位是多少？

      [用户回答后]

      根据你的回答，我把"商业转化"调整为 [新水位]%。
      理由: [一句话]
      新增证据: [一行]

      要确认吗？还是再调一下？
```

### 持续迭代记录格式

```markdown
### 2026-12-15 · 模式 B 局部更新
**触发**: 用户报告"商业转化提升 + 拿到第一个标准化合同"
**更新维度**:
- 商业转化: 45% → 60% (+15%) — 证据: MetaInflow 第一个标准化合同
- 社交势能: 40% → 50% (+10%) — 证据: 行业活动 3 次主动邀请
- 阅读纪律: 90% → 85% (-5%) — 证据: 用户诚实下调，最近 2 个月学习时间减少
**外号**: 保持"连续创业的苦行僧"（核心特征未变，未达 30% 阈值）
**新增里程碑**: 2026-12 · MetaInflow 第一个标准化合同
**归档**: archive/2026-05-03.md
**对比页**: public/compare.html
```

## 模式 C · 里程碑追加（最轻量）

### 触发条件

用户报告**单一事件** —— "我刚 X"、"刚完成 Y"、"昨天发生了 Z"。

例：
- 拿到融资
- 离开 / 加入公司
- 完成某本书 / 课程
- 签下大客户
- 受邀演讲
- 拿到奖
- 项目失败 / 关闭

### 工作流

```
1. 用户描述事件
2. 自动判断这件事会影响哪些维度（基于事件类型 → 维度映射）
3. 询问用户该事件的影响幅度（小/中/大）
4. 对应维度调整水位
5. 在里程碑段追加事件
6. 评估是否触发外号重审视
7. 更新 WENXIN_REPORT.md
8. 自动归档旧版
```

### 事件 → 维度映射（参考表）

| 事件类型 | 主要影响维度 | 典型变化幅度 |
|---|---|---|
| 拿到融资 | 商业转化 ↑ / 社交势能 ↑ | +10% ~ +20% |
| 失去融资 / 公司倒闭 | 商业转化 ↓ / 社交势能 ↓ | -10% ~ -15%（不一定下降，看叙事） |
| 大客户签约 | 商业转化 ↑ | +5% ~ +15% |
| 离开公司主动 | 浪潮判断力 ↑（有判断才离开） | +5% ~ +10% |
| 离开公司被动 | （需要分析背景，不一定下降）| ±5% |
| 完成书 / 课程 | 阅读纪律 ↑ / 相关领域水位 ↑ | +2% ~ +8% |
| 受邀演讲 / 媒体报道 | 社交势能 ↑ | +5% ~ +15% |
| 项目失败 | 不一定下降；可能是"判断力"+（识别失败而退出） | -10% ~ +5% |
| 拿奖 | 社交势能 ↑ / 对应领域 ↑ | +5% ~ +10% |
| MBTI 重测 | 软实力质地（更新模式句） | 维度不变，模式句改 |

⚠️ **不要机械应用** —— 每件事的影响要看用户的叙事。"拿到融资"如果是稀释了控制权，可能是负面信号。

### 持续迭代记录格式

```markdown
### 2027-04-20 · 模式 C 里程碑追加
**触发事件**: A 轮融资 (1500 万)
**用户叙事**: "投资方很认可我们的产品定义，也对我个人的 NVIDIA 背景感兴趣"
**自动推导影响**:
- 商业转化: 60% → 75% (+15%)
- 社交势能: 50% → 65% (+15%)
- 浪潮判断力: 85% → 88% (+3%)
**新增里程碑**: 2027-04 · MetaInflow A 轮融资
**外号**: 演化版 "拿到弹药的苦行僧"（重大变化触发，符合 ≥ 30% 累计阈值）
**归档**: archive/2026-12-15.md
```

## 外号重审视触发条件

外号是**金字塔的灵魂** —— 频繁变化会失去标识性，但**该改要改**。

### 触发条件（满足任一）

1. 任一维度变化 ≥ 30%
2. 主线（对外或对内）发生根本变化
3. 用户主动要求"重新审视外号"
4. 增量更新累计 ≥ 3 次但没改过外号
5. 模式 A 完全重跑时（必须重审视）

### 触发后的对话

```
问心：检测到 [触发条件]。
      当前外号"[现外号]"是不是还匹配？我看到几个变化：
      - [变化 1]
      - [变化 2]

      候选演化方向（不是必须改）：
      A. 保留"[现外号]"——理由：[核心特征还在]
      B. 演化版"[新外号建议]"——理由：[反映了什么变化]
      C. 完全重写——你想强调什么新特征？

      你倾向？
```

### 演化版的写法原则

**尽量保留核心强词，加修饰词反映变化**——不要彻底重写。

例：
- "连续创业的苦行僧" → "拿到弹药的苦行僧"（融资后，加修饰）
- "连续创业的苦行僧" → "退役的苦行僧"（不再创业后，加状态）
- "9 岁脚本小子的连续起死回生" → "9 岁脚本小子的最终归宿"（找到长期方向后）
- "数据田野调查员" → "搬进城里的数据田野调查员"（从草根做到主流后）

### 何时该完全重写

只在**核心强词不再适用**时：
- "苦行僧" → 用户已经"修行结束 / 不再纪律性 / 完全松散" → 整个核心隐喻塌了
- "起死回生" → 用户已经"稳定运行 5 年没失败过"
- "搬运工" → 用户已经"重新回到知识工作"

## 网站同步规则

每次更新后处理网站文件：

| 文件 | 处理 |
|---|---|
| `public/report.html` | 自动重新生成（基于新 WENXIN_REPORT.md） |
| `public/report.pdf` | 自动重新生成 |
| `public/poster.png` | 如外号变化则重生成；否则更新长图上的水位百分比即可 |
| `public/compare.html` | 自动生成 |
| `public/index.html`（个人网站首页）| **不自动改**——只提示用户："首页文案是否要更新？" |

### 给用户的提示模板

```
✓ 报告页 (public/report.html) 已自动更新
✓ PDF 已自动重新生成
✓ 长图已重新生成（外号未变 → 只更新水位）
✓ compare.html 已生成

⚠️ 个人网站首页 (public/index.html) 没有自动更新。
   原因：首页是你精心设计的个人品牌，需要你自己决定要不要改。

   这次更新中可能影响首页的部分：
   - Hero 区的水位数字（如果首页有）
   - 里程碑时间线（新增了 1 项）
   - 卖点三段（[列出有变化的部分]）

   要不要重新跑 web-design 更新首页？(yes/no)
```

## 实操注意

### 不要逼用户更新

「问心」可以**提醒**用户更新（"距上次评估 4 个月了"），但不要**强迫**。

### 增量追问要克制

模式 B 的追问要**只针对勾选的维度**——不要顺便重新追问没变化的维度，那是模式 A 的事。

### 外号变化要慎重

每次外号变化都会让"老朋友"困惑（"你又改外号了？"）。**演化 > 重写**。

### 失败 / 衰退也是信号

不要只追踪"成长"。**衰退、失败、退出**都是真实的，应该被记录。一份只显示 ⬆️ 的报告是失真的。
