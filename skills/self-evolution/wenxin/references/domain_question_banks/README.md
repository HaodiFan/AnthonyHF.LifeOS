# 领域题目库（Domain Question Banks）

「问心」阶段 1（硬实力评估）的辅助组件。

## 这和 `knowledge_probes/` 有什么区别？

很重要的区分：

| | `domain_question_banks/`（这里） | `knowledge_probes/` |
|---|---|---|
| **目的** | 验证用户对该领域的**基础熟悉度** | 验证用户在该领域是否到达 **L4-L5 高水位** |
| **触发** | 用户说"我做过 X 领域" | 用户在 X 领域**水位看起来 ≥ L4 但有可疑信号** |
| **问题难度** | L2-L3 级（基础内行问题）| L4-L5 级（专家级 + 元认知）|
| **题目性质** | "暖场题"——验证基本词汇、基本判断 | "高难度题"——验证认知边界 + 反例 |
| **常用语境** | 用户提到一个新领域时，问 1-2 题确认 | 用户在某领域的水位**令人怀疑**时 |

举例：用户说"我做过电商"。
- 用 `domain_question_banks/ecommerce.md`：问"GMV 和流水的区别是？"——验证基础熟悉
- 用 `knowledge_probes/ecommerce.md`：问"在做退货率优化时，怎么做归因模型？"——验证高水位

## 设计原则

### 1. 暖场题，不是考试

每个领域只问 **1-2 题**，**绝对不超过 3 题**。
目的是确认用户**真的在这个领域里**，不是测能力。

### 2. 答案应该让"在行人"觉得"这都不用想"

好的暖场题：圈内人能 1 秒内答出，圈外人会卡壳。
- ✅ "你刚才提到的电商'四大平台'是哪四个？"（圈内人脱口而出，圈外人答不准）
- ❌ "电商行业的总体规模是多少？"（圈外人查百度也能答）

### 3. 偏好"行业黑话"和"内行隐含知识"

不问课本知识，问**行业内大家都默认知道但外人不知道**的东西。
- ✅ "做电商运营，'618'和'双 11'两个节点哪个对你客户更重要？为什么？"（带行业判断）
- ❌ "什么是 SKU？"（百度词条问题）

### 4. 题目要有"反伪"价值

最好是答错的方式比答对的方式有信息量。
- 如果用户说"618 比双 11 重要"——可能是某些垂直行业（家电）
- 如果用户说"双 11 比 618 重要"——可能是常规品类
- 如果用户说"两个差不多"——可能确实见过完整年的运营
- 如果用户说"我不知道"——可能没真做过运营

## 如何使用

在阶段 1.2（深挖锚点）时，**用户提到一个新领域**：

```
Claude: [识别用户提到了"电商 BI"]
        → 加载 references/domain_question_banks/ecommerce.md
        → 在自然对话中问 1-2 题暖场题
        → 根据回答更新对用户的"领域熟悉度"判断
```

**重要**：
- 不要让用户感觉在被考试
- 题目要**自然地融入对话**——不是"现在我问你 3 个题，请回答"
- 一般 1 题就够，2 题是上限

## 触发后的解读

```
答得自如 + 命中行业默认知识 → 真在行内，可以正常深挖
答得对但生硬 / 用书本式语言 → 接触过但非主业
答错 / 答不出 → 可能没真在这个领域里，水位下调到 L1-L2
```

---

## 自迭代

「问心」每次跑到一个**问题库不存在**的领域时，应该在最终输出后告诉用户：

> 这次我评估你的 [领域 X] 时，发现领域题目库里没有这个领域的暖场题。如果你愿意，我们一起补充几道。

然后用户可以**自己提供**该领域的"内行人秒答外行人卡壳"的问题，写进新文件。

这是「问心」的核心自迭代机制之一——领域题目库**永远不完整**，但每次跑都让它更完整。
