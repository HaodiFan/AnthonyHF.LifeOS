# 示例：Skill 逆向拆解片段

## 用户请求

> 逆推这个 Skill 是怎么设计出来的，准备后续迭代。

## 高水位输出片段

### 产出物证据图

| 模块 | 可观察证据 | 作用 | 证据等级 |
|---|---|---|---|
| description | 包含触发场景和边界 | 语义路由 | E1 |
| 工作流程 | 多阶段执行 | 指导消费者 AI | E1 |
| references | 方法论和模板拆分 | 渐进加载 | E1 |
| evals | 正常/边缘/不应触发 | 回归验证 | E1 |

### 隐性认知任务

| 显性内容 | 隐性认知任务 | 方法论 |
|---|---|---|
| description | 定义语义边界，减少误触发 | should-trigger / should-not-trigger |
| 工作流程 | 把方法论编译成消费者 AI 可执行路径 | 消费者执行模型 |
| references | 控制上下文成本 | 渐进加载 |
| evals | 证明触发和输出稳定 | 回归测试 |

### 中间资产复原

| 阶段 | 中间资产 | 下游消费 |
|---|---|---|
| 需求判断 | PSPS+C | description 和边界 |
| 方法论审视 | 方法论拆解备忘录 | 工作流程 |
| 架构设计 | 文件分工表 | references/assets/scripts |
| 验证设计 | eval case 表 | evals.json |

### 过程步骤示例

| 步骤 | 显性动作 | 隐性认知任务 | 成功标准 |
|---|---|---|---|
| 1 | 写 description | 判断触发边界 | 近似反例不误触发 |
| 2 | 设计主流程 | 把方法论变成 AI 可执行路径 | 只读 SKILL.md 能继续 |
| 3 | 拆 references | 降低上下文负担 | 何时读取清楚 |
| 4 | 写 evals | 检查真实可用性 | 正常/边缘/不触发覆盖 |

## 使用要点

Skill 类产出物的核心不是文件结构，而是消费者 AI 是否能在触发后知道“下一步做什么、何时读什么、何时问人、如何自检”。
