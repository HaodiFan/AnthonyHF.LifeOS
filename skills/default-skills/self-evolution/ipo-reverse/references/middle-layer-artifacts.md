# 中间思考资产复原

高手不会从空白直接跳到成品。中间一定存在过某些思考资产，哪怕没有写出来，也在脑中形成过。本文件用于复原这些资产。

## 1. 常见中间资产

| 中间资产 | 解决的问题 | 典型字段 |
|---|---|---|
| 问题定义 brief | 明确为什么做、为谁做、做到什么程度 | 背景、目标、受众、边界、成功标准 |
| 信息缺口表 | 明确还缺什么证据 | 已知、未知、来源、补齐方式、影响 |
| 假设清单 | 管理默认前提 | 假设、依据、置信度、验证方式 |
| 证据表 | 支撑关键判断 | 证据、来源、可信度、支持的结论 |
| 判断矩阵 | 做取舍和优先级 | 选项、标准、权重、取舍理由 |
| 结构草图 | 组织模块和层级 | 模块、关系、顺序、依赖 |
| 反例清单 | 防止方案脆弱 | 反例、风险、应对、是否覆盖 |
| 质量检查表 | 判断是否做到位 | 检查项、通过标准、失败信号 |
| 下游消费图 | 保证步骤不孤立 | 输出物、被谁使用、在哪一步使用 |

## 2. 复原规则

每个关键阶段至少复原一个中间资产。若无法确认实际存在，使用 `[复原假设]`：

```markdown
**中间资产：问题定义 brief** `[复原假设 · E3 · 置信度：中]`
- 为什么需要它：
- 可能包含：
- 证据来源：
- 下游消费：
```

## 3. 资产选择表

| 产出物迹象 | 优先复原的资产 |
|---|---|
| 有清晰目标和受众 | 问题定义 brief |
| 有大量数据或引用 | 证据表、信息缺口表 |
| 有明显取舍 | 判断矩阵、假设清单 |
| 结构层级很强 | 结构草图 |
| 有风险或边界说明 | 反例清单、质量检查表 |
| 最终内容高度可执行 | 下游消费图、SOP 草案 |
