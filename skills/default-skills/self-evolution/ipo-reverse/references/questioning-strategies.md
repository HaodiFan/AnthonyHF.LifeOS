# 关键未知追问策略库

本文档只在必须追问用户时读取。V2 的默认策略是**主动推演优先**，不是访谈优先。追问只用于校准高影响、无法推断、无法通过反证自验的未知项。

核心原则：**先给出有证据等级的推演，再让用户纠正关键偏差**。人对"纠正别人的错误"比"描述自己的过程"更擅长。

## 追问门槛

追问前先确认这个未知项同时满足：

1. 影响最终 IPO 主链路；
2. 无法从产出物证据、领域方法论、专家常见路径推断；
3. 推错会导致复现路径明显失效；
4. 无法通过正向还原、删步反证、替代路径比较自验。

不满足就不问，标证据等级和假设继续推进。

合格追问格式：

```markdown
我观察到 [证据]，因此推测 [过程/方法论/判断]。
这个点会影响 [后续步骤/复现路径]。
请确认：是 [A]，还是 [B]，还是其他？
```

## 四种核心提问策略

### 策略 1：选项式提问（最常用）

给用户 2-3 个选项，而非开放题。降低认知负担，加快回答速度。

**模式：** "这部分是 A 还是 B？"

**示例：**
- "这部分是先有框架再填内容，还是边写边成型的？"
- "这个数据是你自己调研的，还是从现有报告里提取的，还是有人给你的？"
- "写这一段的时候，你是参考了某个模板，还是从零开始的？"
- "这个决策是你独立做的，还是经过了团队讨论？"

**适用场景：** 判断过程走向、识别输入来源、确认执行方式

**注意：** 选项要覆盖主要可能性，但留一个"其他"出口——"还是其他方式？"

---

### 策略 2：反例式提问

通过问"如果没有做 X 会怎样"来暴露隐性步骤。用户通常记不住"做了什么"，但能清楚地感知"如果少了什么会出问题"。

**模式：** "如果没有做 X，这部分还能做出来吗？"

**示例：**
- "如果没有先做竞品调研，这个产品定位还能写出来吗？"
- "如果跳过数据验证这一步，后面的分析结果还可信吗？"
- "如果没有那次和客户的沟通，这个需求还能定下来吗？"
- "如果把第二步和第三步对调，结果会不同吗？"

**适用场景：** 识别隐性前置步骤、验证步骤顺序、发现依赖关系

**注意：** 如果用户说"没有 X 也能做"，说明 X 可能不是必需步骤，或者是 `[可选输入]`。

---

### 策略 3：极端假设式提问

通过假设极端情况（如完全不懂的人来做）来暴露"专家觉得理所当然但实际上是关键前置知识"的东西。

**模式：** "如果让一个完全不懂 X 的人来做，他第一个会卡在哪里？"

**示例：**
- "如果让一个从没写过商业方案的人来做，他读完你的方案后，第一个做不了的事情是什么？"
- "如果让一个应届毕业生接手这个项目，他需要先补什么知识才能开始？"
- "假设你要把这个工作交给助理，你口头上会怎么一步步交代？"
- "如果做这个的时候你的电脑只有一个空白文档，你第一步会干什么？"

**适用场景：** 暴露领域知识依赖、识别默认假设、还原"从零开始"的路径

**注意：** 这个策略在复杂产出物上特别有效，因为越复杂的产出物，隐性知识越多。

---

### 策略 4：错误理解式提问

故意给出一个"差不多但不完全对"的理解，触发用户的纠正本能。人天生喜欢纠正错误——利用这一点。

**模式：** "我猜这部分是 X 方式做的——如果不是，实际是怎么做的？"

**示例：**
- "我猜这部分是一口气写出来的——如果不是，中间断在哪里？"
- "我推测你是先写了大纲再填充的——如果不是这样，实际过程是怎样的？"
- "看起来这个分析是基于公开数据做的——还是有内部数据源？"
- "我的理解是这个设计是你一个人完成的——有没有其他人参与了某些部分？"

**适用场景：** 几乎所有场景都适用，尤其是用户"说不出来"的时候

**注意：** 错误不要太离谱（会让用户觉得你不专业），也不要太接近（没有纠正空间）。70% 准确率最佳。

## 按场景选择策略

| 场景 | 推荐策略 | 理由 |
|------|---------|------|
| 判断过程的大致走向 | 选项式 | 快速缩小范围 |
| 确认某个步骤是否存在 | 反例式 | 暴露隐性步骤 |
| 挖掘深层前置知识 | 极端假设式 | 暴露默认假设 |
| 用户"说不出来" | 错误理解式 | 用纠正触发表达 |
| 确认步骤顺序 | 选项式 + 反例式组合 | 先给选项，再用反例验证 |
| 区分一口气 vs 分步 | 错误理解式 | "我猜是一口气写的"最能触发纠正 |
| 识别动态触发步骤 | 极端假设式 | "如果遇到 X 情况，你会怎么调整？" |

## 提问节奏控制

### 每轮提问数量
- 每轮最多 3 个问题。
- 总共最多 2 轮。
- 每个问题必须对应一个高影响未知。

### 何时停止提问
- 用户的回答不再带来新信息
- 同一个问题换了提问方式用户仍回答不了（→ 标记 `[假设]`）
- 已完成 2 轮追问。
- 问题不满足追问门槛。

### 提问的递进顺序
1. 先给主动推演模型。
2. 对高影响未知用选项式确认。
3. 对隐性步骤用反例式验证。
4. 对专家默认前提用极端假设式暴露。
5. 用户仍说不清时，标 E5 假设继续推进。

## 用户无法回答时的降级策略

用户无法回答可能因为：隐性知识太深说不出来、确实不记得了、不是本人做的。

### 降级路径

```
选项式提问
  ↓ 用户选不出来
反例式提问
  ↓ 用户说不清
极端假设式
  ↓ 用户仍然无法回答
错误理解式（最后手段）
  ↓ 用户也无法纠正
标记 [假设]，注明置信度，继续推进
```

### 标记假设的格式

当信息无法确认时，在拆解文档中这样标记：

```
**步骤 3：数据验证** [假设 · 置信度：中]
- 假设内容：推测此步骤基于内部数据库进行交叉验证
- 假设依据：产出物中的数据精度超过公开来源能提供的水平
- 验证方式：确认是否有内部数据访问权限
```
