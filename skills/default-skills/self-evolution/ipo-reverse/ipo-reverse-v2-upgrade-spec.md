## 0. 形态判断

| 问题 | 结论 |
|---|---|
| 这是 Skill / SOP / Office / hook / 文档 / 既有 Skill 迭代？ | 既有 Skill 迭代 |
| 为什么值得迭代？ | 当前版本能拆 IPO，但容易过早进入步骤复述，未充分萃取隐性方法论、专家决策逻辑和中间思考资产 |
| 已做过几次，未来预计几次？ | 高频原子能力；每次从产出物沉淀 SOP、Skill、团队训练材料时都会用 |
| 现有 Skill 是否能改而不是新建？ | 能。核心定位仍是从产出物逆向萃取可复现过程，升级的是方法论层和推演机制 |
| 相邻 Skill / Office / 工具 | `neil-skills-creator-v3`、`skill-creator`、`execution-plan`、SOP/培训材料生成 |
| 风险分层 | Deep：高价值、高频、会影响后续 Skill 质量和组织知识沉淀 |

## 1. 概述

| 字段 | 内容 |
|---|---|
| Skill name | `ipo-reverse` |
| 一句话定位 | 从任意产出物逆向复原专家的认知任务、隐性方法论、决策函数、中间思考资产和最终 IPO 链路 |
| 目标用户 | Neil、团队成员、Skill 设计者、需要复现高手过程的人 |
| 直接消费者 AI | 触发后负责主动推演的 Agent |
| 下游动作 | 生成 SOP、训练材料、Skill 规格书、执行手册、复盘材料 |

升级后的核心判断：

> IPO 不是拆解起点，而是萃取完成后的封装格式。真正的起点是复原专家在产出背后的认知任务、方法论选择、判断标准和中间思考资产。

## 2. 问题定义

问题定义句：

> 本 Skill 用于在用户提供已完成产出物时，帮助消费者 AI 主动逆向推演专家如何完成该产出物，通过隐性方法论识别、中间思考资产复原、假设审计和反证校验，产出可被小白复现、可被团队训练、可被 Skill 化的 IPO 拆解文档。

| 问题 | 回答 |
|---|---|
| 要解决什么问题 | 高手的真实能力不在显性步骤里，而在隐性的认知任务、方法论选择、判断标准、中间备忘录和反复自我校验中 |
| 当前版本痛点 | 过早进入 IPO；方法论散落在流程中；中间层没有强制产物；容易问用户太多；缺少方法论竞选和自我推翻机制 |
| 理想状态 | Agent 默认主动推演，只问关键高风险未知；最终不仅能还原动作，还能还原高手为什么这样做、如何判断做对了 |
| 不做会损失什么 | 产出的 IPO 会变成普通 SOP，缺少中间思考与隐性方法论，导致别人照做只能复刻表面动作，无法复刻质量 |

## 3. PSPS+C

| 要素 | 人类维度 | 消费者 AI 维度 |
|---|---|---|
| Persona | Neil / 业务负责人 / Skill 设计者想把高手产出沉淀为组织能力 | 被触发后要像知识萃取专家和过程审计员一样主动推演 |
| Scene | 用户给出文档、方案、代码、对话、系统设计等成品 | 先观察产出物证据，再逆推认知任务和过程链路 |
| Painpoint | 只拆步骤会漏掉高手真正的思考、判断和方法论 | 如果没有中间产物和反证机制，容易给出看似完整但不可复现的流程 |
| Solution | 输出专家复原档案 + 最终 IPO 拆解 | 强制执行方法论识别、证据分级、假设审计、反证循环 |
| Consumer | 人类要拿它复现/训练/Skill 化 | Agent 要知道什么时候推演、什么时候问、什么时候停止问 |

## 4. 触发设计

### 4.1 Should trigger

| 用户表达 | 为什么应触发 |
|---|---|
| “帮我拆解这个产出物是怎么做出来的” | 明确要求从成品逆推过程 |
| “把这份方案背后的高手方法论萃取出来” | 明确要求隐性方法论和认知过程 |
| “这个东西怎么变成 SOP / 培训材料 / Skill” | 需要从产出物沉淀可复现链路 |
| “逆推一下这个文档 / 代码 / 对话的 IPO” | 明确要求 IPO 逆向拆解 |
| “复盘一下这个成果背后的生产过程” | 需要还原过程、假设、判断与中间产物 |

### 4.2 Should not trigger

| 近似但不应触发的表达 | 应转向哪里 | 为什么 |
|---|---|---|
| “总结这篇文章” | 总结/阅读理解 | 提取内容要点，不是还原生产过程 |
| “优化这份方案” | 方案优化 / 领域 Skill | 是正向改进，不是逆向萃取 |
| “帮我写一个类似的文档” | 写作 / 方案生成 | 是创作任务；可先用 IPO-Reverse 拆样例，但不应自动触发 |
| “评价这份文档好不好” | 审查/质量评估 | 评价质量不是还原过程 |
| “设计一个未来执行路径” | `execution-plan` | 没有已完成产出物，属于正向计划 |

### 4.3 Description 草稿

```markdown
从已完成产出物（文档/方案/代码/对话/系统设计）逆向复原专家的认知任务、隐性方法论、决策逻辑、中间思考资产和最终 IPO 链路。适用于知识萃取、SOP 制作、团队培训、Skill 设计蓝图；用户说“拆解过程”“逆推 IPO”“知识萃取”“怎么做出来的”“变成 SOP”“高手方法论”时触发。不处理单纯总结、质量审查、正向方案设计或内容优化。
```

## 5. 输出物定义

### 5.1 最终输出物

| 输出物 | 格式 | 使用者 | 用途 | 是否进入下游 |
|---|---|---|---|---|
| 专家复原档案 | Markdown | Neil / 团队 / Skill 设计者 | 理解高手背后的认知任务、方法论、判断标准 | 是 |
| IPO 拆解文档 | Markdown | 执行者 / 培训对象 / Skill 设计者 | 按步骤复现产出物 | 是 |
| 假设与验证清单 | 表格 | Neil / 后续执行者 | 标记哪些地方需验证或补证据 | 是 |

### 5.2 强制中间层

| 中间层 | 目的 | 是否必须显式输出 | 确认方式 |
|---|---|---|---|
| 产出物证据图 | 只记录产出物里能看到的事实，防止过早脑补 | 必须 | Agent 自检；复杂场景可给用户看 |
| 认知任务与隐性方法论表 | 识别每个显性模块背后实际解决的认知问题和可用方法论 | 必须 | Agent 主动推演，必要时用户校准 |
| 方法论竞选备忘录 | 比较候选方法论，说明为什么选 A 不选 B | 必须 | 高影响方法论选择需标证据等级 |
| 中间思考资产复原 | 复原 brief、假设表、判断矩阵、结构草图等中间物 | 必须 | 如缺失则标 `[复原假设]` |
| 假设与证据台账 | 管理观察、推断、用户确认和未验证假设 | 必须 | 高影响低置信度才追问 |
| 依赖与下游消费图 | 检查每一步输出是否被下游使用 | 必须 | 无下游消费的步骤必须删掉或解释 |
| 反证与重构日志 | 记录至少两轮自我推翻后的修改 | 必须 | 未做反证不得输出最终 IPO |

## 6. 方法论拆解备忘录

| 核心任务 | 本质问题 | 方法论 / Neil 实战方法 | 对流程的影响 |
|---|---|---|---|
| 产出物解剖 | 如何只基于事实拆出最终成品的模块和证据？ | MECE、功能分解、Evidence Ladder | Phase 1 先输出事实证据图，不允许直接写过程 |
| 隐性认知任务识别 | 表面动作背后，专家实际在解决什么认知问题？ | Cognitive Task Analysis、5W1H、专家访谈法 | 每个显性步骤必须写“脑子里在干什么” |
| 方法论选择 | 当前工作领域下有哪些可用方法论，为什么选这个？ | 方法论竞选、领域框架检索、Neil 实战经验 | 不允许直接贴标签，必须给候选、取舍、弃用理由 |
| 中间思考资产复原 | 高手在成品前一定经过了哪些 brief、memo、判断表或草图？ | Process Tracing、工作记忆外化、思考资产化 | 每个关键阶段必须有可交付的中间物 |
| 步骤链路构建 | 如何把中间思考资产转成可执行步骤？ | IPO、SIPOC、Dependency DAG | 步骤必须有输入、动作、输出、下游消费 |
| 主动推演与追问节制 | 如何避免无限询问，同时不硬编关键事实？ | Inquiry Economics、证据分级、置信度管理 | 默认推演，只问高影响且无法验证的未知 |
| 反证校验 | 如何确认过程模型不是事后合理化？ | 正向还原、删步反证、替代路径比较 | 最终 IPO 前至少两轮反证，复杂产出物三轮 |

### 6.1 证据等级

| 等级 | 含义 | 用法 |
|---|---|---|
| E1 直接观察 | 产出物中明确可见 | 可直接作为依据 |
| E2 结构推断 | 由模块关系、依赖关系合理推出 | 标 `[结构推断]` |
| E3 方法论推断 | 由该领域常见专家做法推出 | 标 `[方法论推断]` |
| E4 用户确认 | 用户明确确认 | 可提升关键假设置信度 |
| E5 未验证假设 | 暂时无法验证 | 进入假设审计，高影响时追问 |

### 6.2 方法论竞选规则

每个关键认知任务必须回答：

```markdown
当前认知任务：
所属工作领域：
候选方法论：
1. [方法论 A]：适用点 / 不适用点
2. [方法论 B]：适用点 / 不适用点
3. [方法论 C]：适用点 / 不适用点

最终选择：
- 主方法论：
- 辅助方法论：
- 弃用方法论与理由：

对步骤拆解的影响：
```

## 7. 工作流程

```text
Phase 0：输入门禁与推演策略
  判断是否为已完成产出物
  判断是否需要转向正向计划/总结/审查
  建立推演策略：默认主动推演，只问关键未知

Phase 1：产出物证据扫描
  只记录可观察事实
  用 MECE 拆模块
  标记证据等级和信息缺口

Phase 2：隐性认知任务识别
  对每个模块/关键内容反推“脑子里在解决什么问题”
  判断所属工作领域
  提取专家触发信号、判断标准和取舍点

Phase 3：方法论竞选与中间资产复原
  为关键认知任务列候选方法论
  选择主/辅方法论并说明弃用理由
  复原 brief、memo、假设表、判断矩阵、结构草图等中间资产

Phase 4：过程链路构建
  将中间资产转化为步骤
  每步绑定输入、动作、输出、方法论、隐含假设、成功标准、下游消费
  区分固定、条件触发、自适应
  区分一口气生成、分步执行

Phase 5：反证、重构与收敛
  Round 1 正向还原：按流程能否生成原产出物
  Round 2 删步反证：删掉某步是否影响质量
  Round 3 替代路径：是否存在更短、更稳、更像高手的路径
  必要时重构过程模型

Phase 6：最终 IPO 封装
  输出专家复原档案
  输出 IPO 拆解文档
  输出假设与验证清单
  给出下游使用建议
```

### 7.1 主动推演规则

本 Skill 默认主动推演，不把用户当作主要信息源。

只有未知项同时满足以下条件才追问用户：

1. 影响最终 IPO 主链路；
2. 无法从产出物证据、领域方法论或常见专家路径推断；
3. 推错会导致复现路径明显失效；
4. 无法通过后续反证循环自行验证。

追问限制：

- 每轮最多 3 个问题；
- 总共最多 2 轮；
- 超过后继续推进，标记假设和置信度；
- 问题必须带假设，禁止开放式索取背景。

### 7.2 未知项处理表

| 未知类型 | 处理方式 |
|---|---|
| 可从产出物结构推断 | 直接推演，标 `[结构推断]` |
| 可从领域惯例推断 | 直接推演，标 `[方法论推断]` |
| 不影响主流程 | 不问，放入假设表 |
| 影响主流程但可反证 | 先推演，后验证 |
| 高影响且无法验证 | 追问用户 |

### 7.3 步骤拆解字段

最终 Process 里每个步骤必须包含：

| 字段 | 说明 |
|---|---|
| 显性动作 | 表面做了什么 |
| 认知任务 | 脑子里实际在解决什么问题 |
| 触发信号 | 为什么此时要做这一步 |
| 方法论 | 主方法论和辅助方法论 |
| 选择依据 | 为什么选它，不选别的 |
| 中间产物 | 该步骤生成的 brief / memo / 表格 / 草图 |
| 输入 | 需要什么前置材料 |
| 操作 | 具体怎么做 |
| 输出 | 产出什么 |
| 隐含假设 | 默认了什么前提 |
| 成功标准 | 怎么判断做到位 |
| 失败信号 | 什么说明这步错了或不充分 |
| 下游消费 | 后续哪一步依赖它 |
| 动态类型 | 固定 / 条件触发 / 自适应 |
| 生成模式 | 一口气生成 / 分步执行 |
| 证据等级 | E1-E5 |

### 7.4 异常处理

| 异常 | 处理 |
|---|---|
| 用户只给任务描述，没有产出物 | 提示需要已完成产出物；若要正向路径，转 `execution-plan` |
| 产出物极简单 | 仍做最小方法论识别，但可合并中间层，输出简版 |
| 产出物极复杂 | 分模块处理，每个模块独立做 Phase 1-4，再统一反证 |
| 用户无法回答追问 | 标 E5 假设，注明影响范围，继续推进 |
| Agent 推演后发现方法论不适配 | 重开方法论竞选，替换过程模型 |
| 反证发现某步骤无下游消费 | 删除该步骤，或降级为可选背景输入 |
| 正向还原失败 | 回 Phase 3 或 Phase 4 重构，不在最终 IPO 里打补丁 |

## 8. 架构与文件规划

### 8.1 实现方式决策

| 功能点 | AI 原生能做？ | 实现方式 | 理由 |
|---|---|---|---|
| 主流程和边界判断 | 是 | `SKILL.md` | 每次触发必须读到 |
| 方法论映射和竞选 | 是 | `references/methodology-map.md` | 细节较多，按需读取 |
| 主动推演与追问节制 | 是 | `SKILL.md` + `references/active-inference-rules.md` | 原则在主体，细则在 reference |
| 证据等级 | 是 | `SKILL.md` + `references/evidence-ladder.md` | 主体要能直接执行，reference 给例子 |
| 中间产物模板 | 是 | `references/middle-layer-artifacts.md` | 避免主体过长 |
| 输出模板 | 是 | `references/ipo-output-template.md` | 沿用并升级现有模板 |
| 示例学习 | 是 | `examples/` | 复杂映射通过案例学习 |
| eval 测试 | 否 | `evals/evals.json` | 需要结构化测试集 |

### 8.2 文件结构

```text
ipo-reverse/
├── SKILL.md

├── ipo-reverse-v2-upgrade-spec.md
├── references/
│   ├── methodology-map.md

│   ├── evidence-ladder.md
│   ├── middle-layer-artifacts.md
```

| 文件 | 用途 | 何时读取/调用 |
|---|---|---|
| `SKILL.md` | 主路径、边界、强制原则、Phase 总览 | Skill 触发后必读 |
| `references/methodology-map.md` | 常见工作领域、方法论候选、选择规则 | Phase 2-3 |
| `references/active-inference-rules.md` | 主动推演、追问阈值、未知项处理 | Phase 0 和信息缺口出现时 |
| `references/evidence-ladder.md` | 证据等级、假设标注、置信度规则 | Phase 1 起持续使用 |
| `references/middle-layer-artifacts.md` | 中间产物类型和模板 | Phase 3 |
| `references/questioning-strategies.md` | 定向追问策略 | 只有必须问用户时读取 |
| `references/ipo-output-template.md` | 最终输出模板 | Phase 6 |
| `examples/` | 高水位案例 | 消费者 AI 卡住或实现 eval 时读取 |
| `evals/evals.json` | 回归测试 | 实现后运行 |

### 8.3 渐进加载策略

- `SKILL.md` 放：不可违背的原则、阶段流程、主动推演规则、最终自检。
- `references/` 放：方法论库、证据库、中间产物模板、追问策略。
- `examples/` 放：完整高水位案例，不在普通触发中默认读取。
- `evals/` 放：触发、边界、质量回归测试。
- 不需要 `scripts/`：当前任务以推理、萃取、结构化输出为主，脚本化会降低适应性。

## 9. 测试策略

### 9.1 正常场景

| Prompt | 期望输出 |
|---|---|
| 给一份商业方案，要求“拆解它是怎么做出来的” | 输出证据图、认知任务表、方法论竞选、中间资产、最终 IPO |
| 给一个已有 Skill，要求“逆推这个 Skill 的设计过程” | 识别 Skill 设计方法论、规格书中间产物、eval 和 description 逻辑 |
| 给一段销售对话，要求“萃取成 SOP” | 先复原对话背后的判断、分寸、话术策略，再输出 SOP/IPO |
| 给一个代码模块，要求“逆推开发过程” | 识别需求理解、接口设计、实现、测试、异常处理等隐性步骤 |

### 9.2 边缘场景

| Prompt | 期望行为 |
|---|---|
| 只给任务描述：“帮我拆解怎么做 landing page” | 不输出逆向 IPO；提示需要已完成产出物，或转正向执行计划 |
| 产出物信息不足 | 主动推演；只问高影响未知；最多两轮 |
| 用户要求“别问我，直接推演” | 全部使用证据等级和假设审计推进 |
| 复杂产出物超过 30 步 | 分模块拆解，第一层阶段不超过 7 个 |

### 9.3 不应触发场景

| Prompt | 期望行为 |
|---|---|
| “总结这份文档” | 不触发 IPO-Reverse |
| “帮我改好这份方案” | 不触发；转方案优化 |
| “评价这个文档质量” | 不触发；转审查 |
| “设计一个执行计划” | 不触发；转 `execution-plan` |

### 9.4 质量断言

每个 eval 至少检查：

- 是否默认主动推演，而非无限询问。
- 是否建立产出物证据图。
- 是否识别隐性认知任务。
- 是否做方法论竞选，而非直接贴标签。
- 是否复原中间思考资产。
- 是否标注隐含假设、成功标准、失败信号。
- 是否执行至少两轮反证。
- 是否最终输出 IPO 且能正向还原产出物。
