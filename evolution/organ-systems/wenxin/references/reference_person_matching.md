# 参照人物匹配（Reference Person Matching）

「问心」第三层雷达图的核心机制。**不用通用维度模板**，而是**先找用户最像哪个/哪几个已知人物，然后用那些人物的维度作为衡量标准**。

## 为什么这个机制特别好

### 通用模板的问题

通用模板（"硬实力 / 软实力 / 学习能力 / 沟通 / 领导力"）让所有人在同一坐标系里比较。但**不同的人值得用不同维度衡量**：
- 用"代码能力 / 算法能力 / 系统设计 / 沟通 / 领导力"评估一个程序员是合理的
- 但用同样的维度评估一个 CTO 创业者就**浪费了 ta 的真正特征**——比如"市场嗅觉"、"反共识判断"、"团队凝聚"这些反而看不到

### 参照人物的优势

每个人的**真实形状**都和某些已知人物相似。找到那些人物：
- 用 ta 们的**已知维度**作为衡量标准 → 维度是**经过验证的、有解释力的**
- 用户立刻能理解自己 → "哦我像某种 X 型的人"是巨大的认知 shortcut
- 比抽象维度好记 100 倍

### 拼接是真正的差异化

最关键的一点：**真正稀缺的人不像任何单一已知人物**——ta 们是**混合形态**。

举例：
- 一个"工程能力像早期 Jeff Dean + 商业判断像 Patrick Collison + 沟通风格像费曼"的人 → 这种**特征拼接**比任何单一标签都精准
- 而且这种拼接本身就是**外号的素材**——"Jeff Dean × Patrick Collison × 费曼"这种描述自带传播性

## 工作流程

### Step 1：提取用户的"特征签名"

在阶段 1（硬实力）+ 阶段 2（软实力）评估完成后，提炼出用户最突出的 **3-5 个特征**。

特征要具体到可以"匹配"的程度：
- ❌ "聪明" / "勤奋"（太泛）
- ✅ "9 岁起就生理性追求理解底层" / "6 年坚持每日 2.5 小时定向学习" / "在软硬交界 19 年没换过位置" / "连续创业者，第一次创业 13 个月主动调整方向"

特征的来源：
- **硬实力**：覆盖图里的优势区 + 完成度高的领域
- **软实力**：模式句里反复出现的特征
- **行为痕迹**：时间利用率、学习模式、决策模式
- **轨迹形状**：跨域次数、密度、复利模式

### Step 2：搜索类似人物（必须用 web_search）

**不能凭训练数据里的印象**——理由：
- 训练数据里对某些人物的印象可能过时 / 错误
- 不同领域的"标杆人物"在不断变化
- 必须查最新资料才能给出准确的"维度定义"

搜索策略：
- 按特征搜，不按领域搜：搜"长期主义工程师创业者"比搜"AI 创业者"更精准
- 找具体人物名，不找类型：搜"Patrick Collison early career"比搜"famous CEO"更有用
- 搜该人物的访谈/传记/Wikipedia，提取 ta 的真实维度

### Step 3：决定参照系类型

匹配完后，决定用哪种参照系：

#### 类型 A · 单人参照
用户清晰地像某一个已知人物。直接用那个人的维度。

举例：用户像早期 Steve Wozniak —— 用 "硬件直觉 / 工程极简主义 / 反商业气质 / 长期纯粹度 / 协作中的边缘化"作为维度。

**慎用**：很少有人真的"完全像"某一个人。如果勉强做单人参照，等于把用户压扁成那个人。

#### 类型 B · 多人拼接 ⭐ 最推荐
用户在不同维度像不同人物。**拼接 2-3 个人**的维度作为评估坐标系。

举例：
- 工程能力像：早期 Linus Torvalds（生理性下到底层 / 不容忍模糊）
- 商业判断像：Patrick Collison（早期识别基础设施稀缺位置）
- 学习模式像：Stripe 兄弟里的 John（持续阅读 + 跨域积累）

→ 雷达图维度可能是：「下到底层的生理需求」「基础设施嗅觉」「持续阅读纪律」「反共识决策」「文字表达能力」「商业话语转化」

每个维度的**水位**：用户在该维度上和参照人物对比是 60% / 80% / 90%？

#### 类型 C · 反向参照
用户像某一个已知人物**但弱在某个关键维度**——用 "X minus Y" 模式描述。

举例："早期 Steve Jobs 但没有产品美学敏感度" —— 用 Jobs 的维度，但 Y 维度明确标注 "反向"。

这种参照很有冲击力——它**承认相似性的同时点出差异**，比"你是中国版 X"更精准。

#### 类型 D · 完全独特
真的没有合适参照人物时，**动态选维度**——不强行找参照人物。

这种情况比想象中少。绝大多数人都能找到至少一个合适的参照点。

### Step 4：生成雷达图

5-7 个维度。每个维度需要：

1. **维度名**（来自参照人物的特征 / 或动态选择）
2. **维度定义**（一句话讲清楚这个维度评估的是什么）
3. **用户的水位**（与参照人物对比，0-100%）
4. **证据**（为什么是这个水位）

雷达图的可视化要让用户**一眼看出整体形状**——哪些维度高、哪些维度低、形状像什么（钉子型？平衡型？锯齿型？）。

## 几个关键原则

### 原则 1：诚实参照

**不允许**说"你就是中国版 Elon Musk"。

**允许**说"你在 X、Y 维度像 ta，在 Z 维度只有 60%，在 W 维度完全不同"。

参照不是奉承——参照是诊断工具。AI 必须忍住"找最有名的人来配"的冲动。

### 原则 2：参照人物要"配得上"用户

不能拿"奥巴马"参照一个普通工程师——会显得用户被消费了。
也不能拿"街头说唱歌手"参照一个 CTO——会显得用户被低估了。

参照人物要**和用户在同一个量级 / 同一个语境**，但**特征匹配度高**。

### 原则 3：维度从公开信息提取

每选一个参照人物，必须用 web_search 查 ta 的：
- 访谈
- 传记
- 公开履历
- 同行评价

从中提取 ta **真实的特征维度**，不是 AI 凭印象总结。

例子：
- ❌ AI 凭印象："Linus Torvalds 的特征是 '聪明 + 直接 + 系统思维'"（太泛）
- ✅ 从访谈提取："Linus 的特征签名是：(1) 工程审美严苛到强迫症 / (2) 公开 review 时不留情面 / (3) 几乎不参加技术大会 / (4) 长期纯粹度（30 年 Linux 一件事）"

### 原则 4：拼接的逻辑要可解释

多人拼接时，**说明为什么是这个组合**——不能随机抓 3 个人。组合的逻辑要让用户看到："这个组合的化学反应是 [X]"。

### 原则 5：避免常见的偏差

**避免文化偏差**：不要默认拿西方科技圈名人参照所有人。中国创业者可能更适合参照中国人物。**先问用户/先看信息**了解 ta 的文化语境。

**避免性别偏差**：不要默认拿男性参照所有人。如果用户是女性，参照人物里至少有 1-2 个女性。

**避免年龄偏差**：不要总参照已经成名的"大佬"。年轻参照者（30 岁以下成名）也可以是参照点。

## 输出格式参考

```markdown
## 你最像谁

经过特征匹配，你的能力画像最接近这样的拼接组合：

> **[维度 A] 像 X · [维度 B] 像 Y · [维度 C] 像 Z**

**为什么是这个组合**：
[一段说明，解释这三个人的化学反应]

## 雷达图

[5-7 维 ASCII 或 SVG 雷达图]

| 维度 | 来自 | 你的水位 | 证据 |
|---|---|---|---|
| 维度 A | X 的特征 | 80% | [具体证据] |
| 维度 B | Y 的特征 | 70% | [具体证据] |
| 维度 C | Z 的特征 | 90% | [具体证据] |
| 维度 D | X 的特征 | 50% | [具体证据] |
| 维度 E | Y 的特征 | 60% | [具体证据] |

**整体形状**：[一句话描述这个雷达的形状—— 钉子型 / 锯齿型 / 平衡型]

**这个形状告诉我们**：[一句话洞察]
```

## 自迭代

每次跑「问心」时使用的参照人物 / 维度组合，都应该回流到 skill 里：
- 在 `references/archetypes.md` 记录
- 累积成"参照人物库" + "常见特征-人物映射"
- 下次匹配时可以更快、更准

这是「问心」的关键演化路径之一。
