# 方法论映射与竞选

本文件用于 Phase 2-3：识别隐性认知任务，并为关键任务选择合适方法论。方法论不是装饰，必须改变步骤、字段或检查标准。

## 1. 先识别认知任务

不要直接问“用了什么方法论”。先问：

| 观察对象 | 要反推的问题 |
|---|---|
| 模块结构 | 这里在解决边界划分、论证层级，还是执行顺序？ |
| 数据与证据 | 这里在解决可信度、代表性，还是决策支持？ |
| 话术与措辞 | 这里在解决说服、分寸、异议处理，还是信任建立？ |
| 代码结构 | 这里在解决抽象、接口、状态、性能，还是测试？ |
| 方案取舍 | 这里排除了哪些路径，为什么？ |

## 2. 常见工作领域与候选方法论

| 工作领域 | 常见认知任务 | 候选方法论 |
|---|---|---|
| 结构拆解 | 模块边界、不重不漏、层级组织 | MECE、功能分解树、金字塔原理 |
| 调研分析 | 证据收集、信息缺口、来源可信度 | 5W1H、桌面研究框架、证据三角验证 |
| 战略/商业判断 | 取舍、优先级、竞争位置 | SWOT、波特五力、JTBD、价值链分析 |
| 方案设计 | 从问题到解决方案、约束下取舍 | 设计思维、系统设计、SIPOC、约束分析 |
| 销售对话 | 信任建立、需求澄清、异议处理、推进承诺 | SPIN、MEDDICC、Challenger Sale、分寸原则 |
| 写作表达 | 叙事、论证、读者吸收 | 金字塔原理、SCQA、AIDA、故事弧 |
| 代码开发 | 抽象、接口、实现、测试 | TDD、SOLID、设计模式、状态机、错误处理模型 |
| 流程/SOP | 输入输出、角色、条件分支 | IPO、SIPOC、BPMN、RACI、检查清单 |
| Skill 设计 | 触发边界、消费者 AI 可用性、渐进加载 | PSPS+C、description 边界、消费者模拟测试、eval |
| 复盘学习 | 事实、解释、行动、模式沉淀 | AAR、5 Whys、双环学习、假设审计 |

## 3. 方法论竞选模板

```markdown
### [认知任务名称] 方法论竞选

- 显性内容：
- 本质认知任务：
- 工作领域：
- 触发信号：

| 候选方法论 | 适用点 | 不适用点 | 是否采用 |
|---|---|---|---|
| ... | ... | ... | 主方法论/辅助/弃用 |

最终选择：
- 主方法论：
- 辅助方法论：
- 弃用理由：

对后续步骤的影响：
- 新增字段：
- 新增中间产物：
- 新增质量检查：
```

## 4. 选择原则

1. **领域优先**：先判断任务领域，再选方法论。
2. **问题匹配**：方法论必须解决当前认知任务，不是看起来高级。
3. **可操作**：选择的方法论必须转化成字段、动作或检查项。
4. **可反证**：能说明不用它会漏掉什么。
5. **可组合**：复杂任务允许主方法论 + 辅助方法论。

## 5. 常见错误

| 错误 | 修正 |
|---|---|
| 看到结构就贴 MECE | 先判断是模块边界、论证层级，还是执行顺序 |
| 只列方法论名称 | 写明它改变了哪个步骤、字段或检查标准 |
| 方法论过多 | 只保留主方法论和必要辅助方法论 |
| 忽略弃用理由 | 必须说明为什么不用其他候选 |

## 6. Neil 实战方法入口

当成熟方法论无法解释产出物质量时，标记为 `Neil 实战方法待命名`，但不要替 Neil 命名。输出：

```markdown
这里存在一个稳定但未命名的实战方法：
- 触发场景：
- 核心判断：
- 可观察行为：
- 中间产物：
- 与常见方法论差异：
- 建议 Neil 是否命名：是/否
```
